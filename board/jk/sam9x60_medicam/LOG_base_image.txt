1.2 [ ] (current: WSL2 Debian) isolate the Linux PATH from the Windows PATH
        why: Windows PATH is appended to the WSL PATH (/mnt/c/WINDOWS/system32,
             .../Git/usr/bin, .../Go/bin ...), so Windows make/gcc/find/python shadow
             the Linux ones and the build fails in confusing ways.
        sudo tee /etc/wsl.conf >/dev/null <<'EOF'
        [interop]
        appendWindowsPath = false
        EOF
        # from PowerShell: wsl --shutdown   then reopen the Debian shell
        verify: printenv PATH | tr ':' '\n' | grep -c /mnt/c      -> 0
        verify: which make gcc python3                            -> /usr/bin/*
        note:   still reach the Windows tree via /mnt/d/Source/...

1.3 [ ] apt packages
        sudo apt install -y git gitk meld which sed make binutils build-essential \
             diffutils gcc g++ bash patch gzip bzip2 perl tar cpio unzip rsync file \
             bc findutils libssl-dev libncurses-dev wget ca-certificates
        optional: gh (https://github.com/cli/cli/blob/trunk/docs/install_linux.md)

1.4 [x] git identity
        git config --global user.name "Yuriy Kapoyko"
        git config --global user.email "yury.kapoyko@gmail.com"

1.5 [ ] host quirk when driving WSL from the Windows shell
        - MSYS/git-bash rewrites unix-looking arguments (/etc/x -> C:/Program Files/Git/etc/x)
        - always use:  wsl -d Debian -- bash -lc '<command>'
        - or prefix the single command with MSYS_NO_PATHCONV=1
        - symptom of a violation: a Linux command reporting a C:/... path, or a tool call
          that hangs waiting on stdin.
